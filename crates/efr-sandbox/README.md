# efr-sandbox

## Purpose

The pure logic of the `auto` sandbox. efrd builds a `SandboxSpec` for each contained
call from plain paths (the turn's project, the engine's secret tables, efr's roots, the
grants of an approved exit). `efr-sbx run` reads it, checks it and builds the
`MountPlan`, the bwrap arguments and the policy of the inner stage. Every rule of the
launch lives here, so efrd's early check and the launcher agree, and every rule is
tested without a kernel.

| File | Holds |
|---|---|
| `src/spec.rs` | `SandboxSpec` and its parts: `WriteRoot`, `CacheOverlay`, `Mask`, `Floor`, `NetworkPlan`, `EnvPlan`, `RecordLimits`, `RuntimePaths` with its `DesktopSocket`s, and `JobPlan`, the limits of a job (`efr-sbx run --job`): its call dir lies in the shell dir's `jobs` dir, and a call's never does. A `NetworkPlan::Proxy` must name the call dir's `proxy.sock` (`RuntimePaths::proxy_socket`), and the spec check refuses it beside `Grant::OpenNetwork` (`SandboxError::ProxyWithOpenNetwork`). `RuntimePaths::bus_filter_dir` is a call's `$CALL/bus/` (`BUS_FILTER_DIR`), the dir of its filtered bus sockets (`bus_filter_file`: `system.sock`, `session.sock`), where efrd's bus proxy binds them by relative name. A job's `JobPlan::forward` (`ForwardPlan`, spec version 3) names the job's `$CALL/forward.sock` (`RuntimePaths::forward_socket`, `FORWARD_SOCKET_FILE`), the poll and debounce times and the limit of ports; the spec check refuses it for a job on the host's network (`Grant::OpenNetwork`, `Grant::NetView`, `NetworkPlan::Open`: `SandboxError::ForwardWithHostNetwork`), with another socket (`SandboxError::ForwardSocket`), and for a job in the exit child, a proxy flag that is not the job's network, a poll time of 0 or a limit of 0 or above 8 (`SandboxError::ForwardPlan`). A call's `SandboxSpec::reach` (`ReachPlan`, spec version 4) names the call's `$CALL/reach.sock` (`RuntimePaths::reach_socket`, `REACH_SOCKET_FILE`), the forwarded ports of the conversation's jobs at the prepare and the proxy flag; `check_reach` refuses it for a call on the host's network (`SandboxError::ReachWithHostNetwork`), with another socket (`SandboxError::ReachSocket`), and for a job, the exit child, a proxy flag that is not the call's network, more than `MAX_REACH_PORTS` (32) ports, a port below 1024, the bridge's 3128 or a port twice (`SandboxError::ReachPlan`). `RuntimePaths::moved_file` is `$CALL/moved` (`MOVED_FILE`, from v0.0.4): efrd makes it when the user moves a running call into a job, and the launcher that finds it at the end of the call writes no apply and no shell state. It lies in the call dir, which the plan masks with efr's runtime root |
| `src/forward.rs` | the pure rules of job port forwards: `parse_tcp_table` reads the rows of `/proc/net/tcp` and `tcp6` (a bad line is skipped), `loopback_listens` gives one listen for each loopback port with the address to connect to (`127.0.0.1` for `0.0.0.0`, `::1` for `::`, the IPv4 address of a v4-mapped one; IPv4 wins), `refusal` says why efr never forwards a port (below `MIN_PORT`, the bridge's 3128 in a proxy job, `SERVICE_PORTS`), `Debounce` reports a port after it is stable for `stable_ms` (`ephemeral_stable_ms` in the ephemeral range) and gone after one missing poll, with the time passed in; it reports at most `MAX_REPORTED_PORTS` (64) ports other than service ports over the job's life, only a guard against a flood, because efrd keeps the job's limit of `MAX_JOB_FORWARDS` itself. efrd's side: `peer_uid` finds the uid of the host process that connected, by the peer's address and port (never the row of efrd's own socket), and `v6_holds` says that a host server on `::1` or `::` holds a port. `Frame`: the 28-byte frames between the forwarder and efrd (`Hello`, `Listen`, `Gone`, `Open`, `Data`), and from v0.0.4 between the reach helper of a call and efrd (`Hello` with `REACH_VERSION`, `Reach`, `Unreach`, `Bound`, `Connect`: `FrameKind::is_reach`; each side refuses a kind of the other connection, and a reach takes at most `MAX_REACH_CONNECTIONS` (32) connections), with a hand decoder that refuses an unknown kind, a reserved byte that is not 0, a family other than 4 and 6, an address that is not loopback, a port below 1024 and for a reach kind the bridge's 3128 (`SandboxError::Frame`) |
| `src/fs_view.rs` | `FsView`, the only way this crate reads the file system (with the kinds of a listing, so a scan needs no `lstat` per entry), `resolve`, which follows every link, and `Memo`, which a plan uses so it looks up each path once |
| `src/desktop.rs` | `desktop_socket_path`: the one control socket of a desktop from the variable that names it (`$XDG_RUNTIME_DIR/hypr/<signature>/.socket.sock`, `$XDG_RUNTIME_DIR/$WAYLAND_DISPLAY`, `$SWAYSOCK`, `$I3SOCK`, `$NIRI_SOCKET`, `/tmp/.X11-unix/X<n>` for a local `$DISPLAY`), which efrd and the plan share; `is_desktop_socket`: the place and the file name that the socket of each desktop must have (`wayland-*`, `sway-ipc.*.sock`, `i3/ipc-socket.*`, `niri.*.sock`), so a variable cannot name another socket of the user, such as the session bus |
| `src/plan.rs`, `src/plan/` | `MountPlan`: the ordered mounts, the plan rules (a socket grant below an engine secret or a mask, or in efr's own roots, is refused; a socket grant that reaches, after every link, the system or session bus, a socket of a service manager or a container engine (`SERVICE_SOCKETS`, a copy of efr-permissions' list that a test in efr-daemon keeps equal), a socket below `$XRT/systemd/` or the control socket of any desktop is `SandboxError::SocketGrantRefused`; a desktop grant binds only the socket that `desktop_socket_path` names for the value in the spec, still with the place and the name of `is_desktop_socket` after every link, sets only its variable, and without a socket in the spec is `SandboxError::NoDesktop`), `explain` for `sandbox.explain` and the start dir of a call. `$SCRATCH/jobs` is a floor of every call once efrd made it (`FloorKind::JobOutput`), and a job gets each git dir that it finds at its start as a floor whole (`FloorKind::JobGitDir`). One rule decides the network namespace and the profile: a call keeps the host's network namespace only with an open network, or with `Grant::NetView` and no other network (`net_view()`), and then its inner stage gets the network view's seccomp profile. A `Grant::Unknown` (a grant of a newer efr) fails the plan, and so does `Grant::NetView` beside any grant other than `Write` and `Unmask` (`SandboxError::NetViewMixed`), the rule that efrd keeps too. A proxy plan keeps the private network namespace, binds the call's socket read-only at `$XRT/efr-proxy.sock` (`MountPlan::proxy_socket`) with no `RESOLVE_UNIX` rule for the child, and sets the proxy variables (`PROXY_VARIABLES`, `NO_PROXY_VARIABLES`, `NODE_USE_ENV_PROXY`) to the bridge on `127.0.0.1:3128`. A job with port forwards binds its forward socket read-only at `$XRT/efr-forward.sock` (`MountPlan::forward_socket`, `MountPlan::forward`), with no `RESOLVE_UNIX` rule for the child, and only in a private network namespace. A call with a reach binds its reach socket read-only at `$XRT/efr-reach.sock` (`MountPlan::reach_socket`, `MountPlan::reach`) the same way. A filtered bus (`Grant::BusFilter`, phase E) binds the call's own socket `$CALL/bus/<bus>.sock` read-only where a D-Bus client looks with no variable (`RuntimePaths::inside_bus_socket`: `/run/dbus/system_bus_socket` over an empty tmpfs on `/run/dbus`, or `$XRT/bus`), gives the child `RESOLVE_UNIX` on exactly that place, and sets `DBUS_SYSTEM_BUS_ADDRESS` or `DBUS_SESSION_BUS_ADDRESS`; with no `/run/dbus` the plan fails (`SandboxError::NoSystemBus`), and the spec check refuses it beside `Grant::Bus` of the same bus (`SandboxError::BusFilterWithBus`) |
| `src/args.rs` | the bwrap argument list, `FdTable` (one descriptor per bind, never reused) and `LaunchFds` |
| `src/layers.rs` | `CacheLayers`: the cache overlays that `efr-sbx layers` mounts after bwrap's setup, and the mounts inside each cache that move onto it. Each `CacheLayer` says if it is fresh (its dirs in the staging tmpfs) or keeps the conversation's layer: in the `tmp` mode, a cache with `CacheOverlay::keep` (`sandbox.keep_downloads`) keeps its layer as in the `overlay` mode, and the plan binds its layer dir like one of that mode, under the same layer lock |
| `src/layers/deletes.rs` | `CacheDeletes`: the paths that a call deleted in its private cache layers (the whiteouts of each upper layer, read through `LayerView`), for `SandboxSummary::cache_deletes`, with the limits that keep `result.json` small |
| `src/landlock.rs` | `LandlockPolicy` and `FsAccess` as data; no `RESOLVE_UNIX` rule without a socket grant; a network view call also handles the TCP bind and connect rights with no rule (`deny_tcp`); `LandlockPolicy::bridge`, the bridge's own domain: only `RESOLVE_UNIX` on the proxy socket, no file right, no TCP; `LandlockPolicy::forward`, the forwarder's own domain: only `RESOLVE_UNIX` on the forward socket, no file right, the TCP bind right handled with no rule (`deny_tcp_bind`) and TCP connect left to the job's own loopback; `LandlockPolicy::reach`, the reach helper's own domain: only `RESOLVE_UNIX` on the reach socket, no file right, the TCP connect right handled with no rule (`deny_tcp_connect`) and TCP bind left to the call's own loopback; `LandlockPolicy::bus_proxy`, the domain of `xdg-dbus-proxy` (phase E): read and run only its program, the library dirs (`BUS_PROXY_READS`) and the loader's cache (`BUS_PROXY_FILES`, file rights only, `FsAccess::READ_FILE`), `RESOLVE_UNIX` on each real bus, `MAKE_SOCK`, `REMOVE_FILE` and `RESOLVE_UNIX` in its socket dir only (`FsAccess::SOCKET_DIR`), no TCP |
| `src/seccomp.rs` | `SeccompProfile`: the deny list as data. `phase1()` for every contained call; `net_view()` for a call with `Grant::NetView`: only `AF_UNIX` and `AF_NETLINK` sockets, only the `ROUTE` and `SOCK_DIAG` netlink protocols, and `listen` and `pidfd_getfd` refused; `bridge()` for the bridge of a proxy call: only `AF_UNIX` sockets, and `bind`, `listen`, `execve`, `execveat`, `ptrace` and `pidfd_getfd` refused; `forward()` for the forwarder of a job: only `AF_UNIX`, `AF_INET` and `AF_INET6` sockets, and the same six calls refused; `reach()` for the reach helper of a call: only `AF_UNIX`, `AF_INET` and `AF_INET6` sockets, and `execve`, `execveat`, `ptrace` and `pidfd_getfd` refused, while `bind` and `listen` stay; `bus_proxy()` for `xdg-dbus-proxy` (phase E): only `AF_UNIX` sockets, and `ptrace` and `pidfd_getfd` refused; it binds and listens, and the wrapper's own exec of the program runs after the filter, so `execve` stays and the Landlock domain limits what it can run |

## Tier

Tier 1. `efr-sbx`, `efr-shell` and `efr-daemon` depend on it.

## Allowed dependencies

`efr-protocol`, for the wire types that the spec and the result carry (`Grant`,
`CacheMode`, `SandboxSummary`, `SurfaceChange`, `SandboxStatus`). Third-party crates:
`serde`, `serde_json` and `thiserror`.

The crate must never reach tokio (`xtask/src/deps.rs` forbids `efr-sandbox -> tokio`),
so it does not depend on `efr-stdx`; the few paths it needs come in the spec as plain
paths (`RuntimePaths`). The secret tables stay in `efr-permissions`: efrd passes their
paths, so this crate needs no `efr-permissions` edge.

## Invariant

Nothing here decides alone what a sandboxed call may do with more rights than the spec
gives. A mask always wins over a floor, a floor always wins over a widening, the home
directory is never a write root, a link that a call could change never moves a floor or
a pin, and the records that a call reports are untrusted data. A cache delete counts
only when the lower entry exists, never at or below a pin, a mask or a moved mount.
No IO except through `FsView` and `LayerView`, no unsafe code, no async.

## Tests

Run the tests of this crate alone, without the rest of the workspace:

```sh
cargo nextest run -p efr-sandbox
```

The tests use `testing::FakeFs`, a file system in memory with links and sockets, and
upper layers in memory for the cache deletes. No
kernel sandbox, no network and no zsh: the real-bwrap tests belong to `efr-sbx` and run
under `just test-sandbox`.
