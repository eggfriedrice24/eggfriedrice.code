# Conventions

The rules inside a crate. `cargo xtask tidy` enforces the ones marked (tidy); the
allowlists it uses are data at the top of `xtask/src/tidy.rs`. Keep this file current:
a rule that changes changes here first. The dependency rule between crates is in
`ARCHITECTURE.md`.

These rules are the content of `CONVENTIONS.md`. `cargo xtask tidy` enforces the ones marked (tidy).

## Module layout

- `src/lib.rs` is a table of contents: a `//!` crate doc of at most one screen stating purpose, allowed dependencies and what does not belong here; `mod` declarations; one `pub use` block of the crate's public surface. No logic in `lib.rs`.
- Children of a module live in a directory named after it: `foo.rs` declares `mod bar;` and `foo/bar.rs` holds it (the 2018 layout; no `mod.rs` files, tidy). codex and rust-analyzer use the same layout.
- Unit tests live in `foo/tests.rs` under `#[cfg(test)] mod tests;` at the end of `foo.rs`, never inline and never as a sibling `foo_tests.rs` (tidy rejects `*_tests.rs` and inline `mod tests {`).
- One type per file for anything with more than one `impl` block or more than one screen of methods; small value types may share a file named for the concept (`ids.rs`, `error.rs`).
- Binaries keep `main.rs` to argument parsing, tracing setup and a call into `run.rs`. Everything in a bin crate is `pub(crate)`.
- A crate's README states: purpose, the tier, allowed dependencies, the invariant it protects, how to run its tests without the rest of the workspace.

## Naming

| Thing | Rule | Example |
|---|---|---|
| Crate | `efr-<context>`, kebab-case, a noun | `efr-permissions` |
| Library | `efr_<context>` | `efr_permissions` |
| Binary | short, no prefix repetition | `efrd`, `efr` |
| Module | snake_case noun; verbs only for process modules | `run.rs`, `reconcile.rs` |
| Wire method | `noun.verb` on the wire, `noun_verb.rs` as the file and `NounVerb` as the params type | `conversation.subscribe`, `methods/conversation_subscribe.rs`, `ConversationSubscribe` |
| Event | `Event::<Noun><PastParticiple>` | `TurnStarted`, `ApprovalRequested`, `CwdChanged` |
| Error | `<Crate>Error` enum per crate, variants named for what failed, not where | `StoreError::Busy`, `ProviderError::RateLimited` |
| Actor pair | `XActor` (owns state, runs the loop) and `XHandle` (`Clone + Send`) | `ScreenActor`, `ScreenHandle` |
| Trait for a boundary | the role, not `I` or `Trait` suffix | `Screen`, `PtyHolder`, `Provider`, `Tool`, `SecretStore` |
| Feature | kebab-case, one adjective or noun | `local-pty`, `screen-ghostty`, `keyring`, `conformance` |
| Env var | `EFR_` prefix, screaming snake | `EFR_LOG`, `EFR_SCREEN`, `EFR_DATA_DIR` |
| Migration | `NNNN_<noun>.sql`, four digits, never renumbered | `0001_events.sql` |
| Fixture | `<case>.ndjson` or `<case>.json`, lowercase, words joined by `_` | `cwd_move_between_turns.ndjson` |

## Visibility

- `unreachable_pub = "warn"` (as in rust-analyzer): an item is `pub` only if it is re-exported from `lib.rs`; otherwise `pub(crate)`.
- No glob re-exports (`pub use foo::*`) and no `prelude` modules; a reader must find a name by following `lib.rs`.
- `#[non_exhaustive]` on every wire enum in `efr-protocol` and on every error enum; matches outside the owning crate use a wildcard arm. The one deliberate exception is the `Method` enum, matched exhaustively in `efr-daemon/src/methods.rs` so a new method cannot ship without a scope.
- Constructors over public fields for anything with an invariant; plain `pub` fields for serde wire structs.

## Docs

- Every `pub` item in tier 0 and tier 1 crates has a doc comment (`missing_docs = "warn"` for those crates, set in each manifest's `[lints]` override; the rest of the workspace is exempt until it stabilises).
- `rustdoc::broken_intra_doc_links = "deny"`; CI runs `cargo doc --no-deps` with `-D warnings`.
- Doc tests are off (`doctest = false`) in every crate except `efr-stdx` and `efr-protocol`; examples elsewhere go in `examples/` or tests.
- `ARCHITECTURE.md` follows the rust-analyzer shape: a map of the crates, the invariants, where to find things, and the threading model. `docs/protocol.md` is generated by `cargo xtask protocol-docs` from `efr-protocol` with the `schema` feature (schemars 1.2.2) and never edited by hand.
- Comments explain why, never what; a `// NOTE:` or `// SAFETY:` prefix marks the two kinds a reviewer must read.

## Error types

- Library crates use `thiserror` 2.0.21 enums; `anyhow` 1.0.104 is allowed only in `efr-daemon/src/main.rs`, `efr-cli`, `xtask` and tests. A tidy rule rejects `anyhow` in any other `Cargo.toml`.
- Each crate has exactly one public error enum in `error.rs`. Variants carry structured data (`path: PathBuf`, `seq: Seq`), never preformatted strings. `#[source]` chains are preserved; a `Display` message says what failed in one sentence without the source's text.
- Wire errors: `efr_protocol::ErrorFrame { id, error: { code: ErrorCode, message, data } }` with `ErrorCode` as a closed set (`ProtocolMismatch`, `Unauthorized`, `Forbidden`, `NotFound`, `Conflict`, `Busy`, `Overflow`, `Cancelled`, `Invalid`, `Internal`). The only `From<DaemonError> for ErrorFrame` lives in `efr-daemon/src/error.rs`; no other crate knows the mapping.
- `unwrap_used`, `expect_used` and `panic` are `deny` outside tests (`allow-unwrap-in-tests`, `allow-expect-in-tests`, `allow-panic-in-tests` in `clippy.toml`, the codex and nushell setting). The escape hatch is `#[expect(clippy::unwrap_used, reason = "...")]` on the smallest item. Infallible-by-construction cases use `match` with an `unreachable!()` arm that states the invariant.
- Errors are logged once, at the boundary that drops them: a method handler, an actor loop or `main`. Library crates return them.

## Logging and tracing

- `tracing` 0.1.44 everywhere; the `log` crate is forbidden by `deny.toml` bans.
- Spans: one per connection (`conn_id`, `surface`, `uid`), one per turn (`conversation_id`, `turn_id`), one per tool call (`tool`, `call_id`), one per provider request (`provider`, `model`, `request_id`). Field names are snake_case and stable because the optional JSON log file is searched with grep.
- `#[tracing::instrument(skip_all, fields(...))]` on actor entry points and method handlers; never on hot paths (`feed`, `vt_write`, the PTY reader).
- Levels: `error` for a failed user-visible operation, `warn` for degraded but continuing (a refresh retry, a dropped slow subscriber), `info` for lifecycle (start, ready, shell spawned, login completed), `debug` for per-request detail, `trace` for bytes (never on by default).
- Secrets never reach a field: tokens are `secrecy::SecretString` (0.10.3) whose `Debug` is redacted, request headers go through `efr_http::redact`, and the zsh plugin's `ShellContext` is logged without `last_command`.
- Subscriber setup is only in `efr-daemon/src/telemetry.rs` and `efr-cli/src/main.rs`: `EnvFilter` from `EFR_LOG` (default `info,efr_=debug` under `cargo run`, `info` as a service), `tracing-journald` 0.3.2 when `JOURNAL_STREAM` is set, otherwise a compact stderr layer; an optional JSON file layer through `tracing-appender` 0.2.5 under `$XDG_STATE_HOME/efr/logs/` (whether it is on by default is undecided).

## Config

- One file, `$XDG_CONFIG_HOME/efr/config.toml`, parsed by `efr-daemon/src/config.rs` into `Config` with `#[serde(deny_unknown_fields)]` (`toml` 1.1.6, `serde` 1.0.229). Precedence: built-in defaults, then the file, then `EFR_*` environment variables, then flags. `efr config show` prints the effective result with the source of each value.
- Other crates receive plain config structs (`ShellConfig`, `ProviderConfig`, `StoreConfig`) by value from the daemon. No global config, no `once_cell` config, no crate reads the environment except `efr-stdx::env` and the daemon.
- Paths come from `efr_stdx::paths` (`etcetera` 0.11.0 for XDG): config `$XDG_CONFIG_HOME/efr/`, data `$XDG_DATA_HOME/efr/` (database, recordings, scratch, secrets, memory later), state `$XDG_STATE_HOME/efr/` (logs), runtime `$XDG_RUNTIME_DIR/efr/` (socket, `daemon.json`). `EFR_DATA_DIR` and friends override each root for tests.

## Async and actor rules

- One tokio 1.53.2 multi-thread runtime, created in `efr-daemon/src/main.rs` and `efr-cli/src/main.rs`. Library crates never create runtimes and never call `block_on`; functions that need a runtime are `async fn`.
- State is owned by actors, not shared: one actor per conversation, one `StoreWriter`, one `ShellSessions`, one `ScreenActor` per screen. Communication is `tokio::sync::mpsc` with bounded capacity (default 64) and `oneshot` replies. A handle type is the only public API of an actor.
- No lock is held across an `.await` (`await_holding_lock = "deny"`, `await_holding_invalid_type` for tokio guards, as in codex). `std::sync::Mutex` is fine for short critical sections; `tokio::sync::Mutex` only when the guard must live across an await, which should be rare and commented.
- Time is injected: anything that schedules, retries or expires takes a `Clock` (`efr_stdx::time::Clock`, `SystemClock` in production, `TestClock` in tests). `tokio::time::sleep` appears only inside `SystemClock`. This is what lets provider refresh timing and lease expiry be tested without waiting.
- Randomness is injected the same way (`Rng` trait, `rand` 0.10.3 behind `SystemRng`, a seeded `TestRng`).
- Blocking work (SQLite reads, file hashing) runs in `spawn_blocking`; the only code that is allowed to block a tokio worker is the PTY `pre_exec` closure.
- Backpressure is explicit: every fanout (subscriptions, PTY output) has a bounded queue per consumer, and overflow closes that consumer with `ErrorCode::Overflow` carrying `last_seq`, never slows the producer.
- `cfg(feature = ...)` may appear only in named files: `efr-daemon/src/screens.rs` (`screen-ghostty`), `efr-daemon/src/shells.rs` (`local-pty`), `efr-credentials/src/lib.rs` (`keyring`, one `mod` line), `efr-screen/src/lib.rs` (`conformance`, one `mod` line), `efr-protocol/src/lib.rs` (`schema`, one `mod` line) (tidy).

## Unsafe policy

- `unsafe_code = "deny"` in `[workspace.lints.rust]`. The one module per crate that needs it opts out with `#[allow(unsafe_code)]` on the module item in `lib.rs` plus a module doc explaining why, and `cargo xtask tidy` holds the allowlist of files in which the token `unsafe` may appear: `crates/efr-pty/src/local_holder.rs` at milestone 1, `crates/efr-fdpass/src/lib.rs` from milestone 5. Any other `unsafe` fails CI.
- `unsafe_op_in_unsafe_fn = "deny"`, `clippy::undocumented_unsafe_blocks = "deny"`: every block has a `// SAFETY:` comment naming the invariant, following nushell's unsafe policy, including the system behaviour relied on (what `pre_exec` may call, which fds are open).
- FFI goes through `rustix` 1.1.5 and `nix` 0.31.3 before `libc` 0.2.190; raw `libc` calls are allowed only in the allowlisted files.
- `libghostty-vt` is consumed through its safe API only; `efr-screen-ghostty` has no unsafe. If a future pin needs a hand-written trampoline for the semantic prompt effect, it goes in `efr-screen-ghostty/src/ffi.rs`, added to the tidy allowlist in the same commit, following herdr's pattern of local trampolines.
